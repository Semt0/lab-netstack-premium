# CP3: IPv4 数据报抓包

## 实验环境与结果

拓扑：cp3ns1 (cp3veth1-2, 10.33.1.1/24) -- cp3ns2 (cp3veth2-1, 10.33.1.2/24)。

两端通过 bypassKernel 设置 INPUT、OUTPUT、FORWARD DROP，并关闭内核 IPv4 转发。
发送端运行 test/cp3/send_ipv4_demo.c 编译生成的 tmp/send-ipv4-demo，指定目的 IP 与下一跳 MAC，添加 /32 手动路由，通过实现的 sendIPPacket 发送协议号 253、载荷 lab2-cp3 的数据报。
接收端 tcpdump 捕获一个包；本实验验证 IPv4 构造、发送及报文字段，不验证动态路由或多跳转发。

证据：capture.typescript、send.typescript、ipv4.pcap。两份终端记录均正常结束。
抓包时间为 2026-10-27 08:56:38 UTC。

读取命令（从仓库根目录执行）：

```bash
sudo tcpdump -nn -e -vvv -XX -r checkpoints/cp3/ipv4.pcap
```

## 实际捕获字节

```text
0x0000: 7675 a67f 1b5f 4227 0d8e e9dd 0800 4500
0x0010: 001c 0000 4000 40fd 23a1 0a21 0101 0a21
0x0020: 0102 6c61 6232 2d63 7033 0000 0000 0000
0x0030: 0000 0000 0000 0000 0000 0000
```

以下偏移从以太网帧起始位置计算，使用十进制：

| 字节偏移 | 实际值 | 含义 |
| --- | --- | --- |
| 0-5 | 76 75 a6 7f 1b 5f | 目的 MAC：76:75:a6:7f:1b:5f |
| 6-11 | 42 27 0d 8e e9 dd | 源 MAC：42:27:0d:8e:e9:dd |
| 12-13 | 08 00 | EtherType 0x0800，载荷为 IPv4 |
| 14 | 45 | 高四位 0100 表示版本 4；低四位 0101 表示首部长度 5 个 32 位字，即 20 字节 |
| 15 | 00 | DSCP 与 ECN 均为 0 |
| 16-17 | 00 1c | IPv4 总长度 28 字节，包含 20 字节首部和 8 字节载荷 |
| 18-19 | 00 00 | Identification 为 0 |
| 20-21 | 40 00 | 三位标志为 010，即 DF=1、MF=0、保留位=0；13 位片偏移为 0 |
| 22 | 40 | TTL 为 64 |
| 23 | fd | 协议号 253；载荷直接使用测试字符串，没有 TCP/UDP 首部 |
| 24-25 | 23 a1 | IPv4 首部校验和 0x23a1；独立计算含校验和首部的一补和为 0xffff，校验通过 |
| 26-29 | 0a 21 01 01 | 源 IPv4 地址 10.33.1.1 |
| 30-33 | 0a 21 01 02 | 目的 IPv4 地址 10.33.1.2 |
| 34-41 | 6c 61 62 32 2d 63 70 33 | 依次对应 ASCII 字符 l、a、b、2、-、c、p、3，组成 lab2-cp3，无结尾 NUL |
| 42-59 | 18 个 00 | 以太网填充，不属于 IPv4 数据报或其载荷 |

IPv4 从帧偏移 14 开始。60 字节帧由 14 字节以太网头、28 字节 IPv4 数据报和 18 字节填充组成；本次捕获不包含以太网 FCS。
